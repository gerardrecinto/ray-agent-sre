How it works

One /metrics endpoint for the compute layer and the agent layer on top of it.

1

Wrap each node

A decorator times every call, retries on exception up to a limit, and counts runs, errors and retries per node. It does not import LangGraph, so any callable works.

2

Track the whole run

A context manager around the compiled graph records end-to-end runs, errors and latency, on top of the per-node series.

3

Scrape one surface

The server also reads node, actor and task state from Ray's state API and serves everything on port 9100, with a Grafana dashboard that matches.

Run it

Python 3.12. It starts a local single-node Ray cluster.

python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m ray_agent_sre.server --port 9100 --interval 5
curl localhost:9100/metrics
docker build -t ray-agent-sre .
docker run -p 9100:9100 ray-agent-sre

Import grafana/dashboard.json into Grafana. Kubernetes manifests are in k8s/.

What this does not do
  • It is a proof of concept, run against a single-node local Ray cluster. It has not been run against a production multi-node cluster.
  • Ray does not expose per-node available CPU, so available capacity is tracked only for the whole cluster.
  • The sample deployment starts its own in-process Ray. Pointing it at an existing cluster is a RAY_ADDRESS change that has not been tested.
